### Session Memories & Repository Context
- To add a new `RealityArchetype`, it must be appended to the `RealityArchetype` enum (`reality_types.rs`), added to archetype lists and handlers (`engine.rs`), mapped to a numeric ID and color profile (`lib.rs`), given a conflict rating (`world.rs`), visually defined in WGSL shaders (`shader.wgsl`), and added to UI dropdowns (`index.html`).
- `ActionConditionedSampler` in `reality-genie/src/dit.rs` supports Classifier-Free Guidance (`sample_next_frame_cfg`) by combining conditioned and unconditioned model passes with a configurable `guidance_scale`.
- `Primitive::GenieDit` in `reality-engine/src/lambda.rs` (visual color in `visual_lambda.rs`) evaluates `(GENIE_DIT "prompt")` spells in `Engine::execute_side_effect` to trigger spatiotemporal DiT reality anomalies.
- Playwright E2E tests in `verification` wait for the `#ui-layer` to become visible. If a WebAssembly panic or WebGPU validation error occurs during engine startup, the loading screen will hang and tests will fail with a timeout.
- In `reality-engine`, floating text or chat bubbles can be displayed above an NPC in the UI by setting the `chat_message` field on its `RealityProjector` representation to `Some((message_string, crate::projector::get_current_timestamp()))`.
- `Engine::update` in `reality-engine/src/engine.rs` polls predicted trajectory latents from `GenieBridge`, decodes them via `LatentVoxelDecoder::decode_splat_floats_from_latents_vec`, and instantiates interactive 4D animated splat entities (`Splat4DPlayer`).
- If `cargo install trunk` fails due to yanked dependencies, run `./setup_dev.sh` in the repository root to automatically download and install a pre-compiled `trunk` release.
- Continuous diffusion models outputting float-based heightmaps are preferred over `DiscreteDiffusion` for procedural terrain generation in `reality-engine` to inherently avoid the terracing and quantization artifacts caused by mapping elevation to discrete categorical tokens.
- Live gameplay player inputs (`WASD`, Jump, CastSpell) captured in `Engine::process_keyboard` (`reality-engine/src/engine.rs`) stream into `GenieBridge::request_action_dit_rollout` during `Engine::update` to trigger background spatiotemporal trajectory predictions.
- In WebGPU implementations within `reality-engine` (e.g., in `lib.rs`), dynamic buffers like `instance_buffer` must track their maximum allocated capacity (`max_instances`). When `num_instances` exceeds this capacity, the buffer must be explicitly reallocated to a larger size to prevent 'Write range does not fit in Buffer' validation errors.
- `GenieBridge` in `reality-engine/src/genie_bridge.rs` integrates action-conditioned DiT trajectory rollouts via `request_action_dit_rollout` and exposes generated trajectory latents in `latest_action_dit_latents`.
- To support headless Playwright E2E verification, `reality-engine` features a Canvas 2D CPU fallback renderer (`render_cpu`) that automatically starts when WebGPU is unavailable or when `?renderer=cpu` is in the URL search query, projecting the active 3D coordinates and elements as a wireframe/point cloud.
- `HierarchicalCaptioner` in `reality-genie/src/dataset.rs` maps semantic high-level intent descriptions into discrete player action token sequences and synthetic token captions for multimodal DiT training and conditioning.
- The Trunk build configuration for WebAssembly uses `<link data-trunk rel="rust" />` in `reality-engine/index.html`. Specifying an incorrect or unnecessary `data-target-name` attribute that mismatches the target package defined in `Cargo.toml` causes 'cargo artifacts not found for target crate' errors.
- `reality-genie/src/dit.rs` implements an action-conditioned Spatiotemporal Diffusion Transformer (`ActionConditionedDiT`) and rollout engine (`ActionConditionedSampler`) in Rust using HF Candle, featuring `ActionConditioningEmbedder`, `FrameAnchorBuffer` for drift control, `CausalTemporalAttention`, and `SpatiotemporalDitBlock` with AdaLN adaptive normalization.
- In `reality-engine`, an NPC's health is explicitly tracked by the `health` float property on their `NpcBehavior` struct. Player vitality is represented by the `fidelity` float property on their `RealityProjector.reality_signature`.
- When implementing background worker threads in `reality-engine` (e.g., inside `GenieBridge`), standard OS threads (`std::thread::spawn`) must be explicitly gated behind `#[cfg(not(target_arch = "wasm32"))]` because the engine targets WebAssembly, which lacks native OS thread support.
- Headless Playwright UI verification tests for WebGPU applications like `reality-engine` are protected against GPU-less sandbox panics by a Canvas 2D CPU fallback renderer that automatically activates when WebGPU is unavailable.
- `RollingLatentContext` in `reality-genie/src/dit.rs` maintains a fixed-capacity FIFO queue of frame latents to assemble context tensors in constant time ($O(1)$) during streaming diffusion forcing inference, supporting `rewind`, `to_checkpoint`, and `from_checkpoint_cpu`.
- In `reality-engine`, the core 2D noise heightmap logic is isolated in `Chunk::map_height` to allow independent unit testing for terrain continuity (e.g., verifying `max_diff <= 3` between adjacent coordinates) without interference from procedural structures.
- To avoid `QuotaExceededError` crashes in `reality-engine` caused by eagerly saving large worlds to fallback storage, functions like `save_to_local_storage` must be executed conditionally inside the asynchronous `wasm_bindgen_futures::spawn_local` block, only triggering if the primary async `save_to_indexed_db` returns false.
- The engine supports background generative world extension via a simulated Geometric Context Transformer (GCT) in `reality-genie/src/gct.rs` (using `TrajectoryMemory`, `PagedKVCache`, `AnchorContext`, and `KeyframeWindow`). This pipeline is exposed via `GenieBridge::request_iterative_extension` and triggered by the `EXTEND` (Primitive::Extend) spell primitive.
- `reality-genie/src/bin/train_dit.rs` provides an AdamW training binary that computes MSE noise prediction loss on trajectory latents and serializes trained `ActionConditionedDiT` model weights to `action_dit_model.safetensors`.
- When initializing the `WgpuState` struct in `reality-engine`, variables like `device` and `camera_buffer` must not be consumed inline after being moved. Dependent resources like bind groups should be created before the struct literal to prevent 'borrow of moved value' compilation errors.
- `LatentVoxelDecoder::check_solidity_collision` in `reality-genie/src/vqvae.rs` evaluates entity bounding spheres against decoded latent voxel coordinates, returning penetration depth to allow `Engine::update` to resolve collision penetration and prevent phasing through neural world geometry.
- `FrameAnchorBuffer` calculates trajectory drift variance via `compute_drift_variance`, which is formatted into the HUD label telemetry string in `Engine::get_node_labels_flat`.
- To verify WASM compatibility and surface WebAssembly-specific compiler warnings during development of `reality-engine`, run `cargo check --target wasm32-unknown-unknown`.
- `compute_collision_boundary_loss` in `reality-genie/src/bin/train_dit.rs` computes a boundary penetration penalty between adjacent spatial tokens to reinforce physical object solidity during DiT training.
- In `reality-engine`, WebXR gesture recognition (e.g., Open Palm and Fist) in both VR and AR sessions relies on calculating the squared distance from the wrist to all five fingertips. Actions must be debounced using per-controller state arrays (size 4) like `last_palm_pressed` and `last_fist_pressed` to prevent per-frame spamming.
- `TrajectoryDirector` in `reality-genie/src/dit.rs` stabilizes predicted frame latents against long-horizon drift by checking `FrameAnchorBuffer::compute_drift_variance` against `max_drift_threshold` and blending diverging frames with cached anchor keyframes.
